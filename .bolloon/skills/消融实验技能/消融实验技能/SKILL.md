# 消融实验技能:拆掉一个看缺什么

> **"拆掉一个看缺什么,不是加一个看多了什么。"**  
> **消融实验的核心是归因:哪个组件真正有效?**  
> **不检测假阳性,你永远不知道结果是否可信。**

---

## 一句话心法

> **"拆一个,看缺啥;指标独立,基线先行。"**  
> **消融实验不是"加功能看效果",是"移除功能看影响"。**

---

## 核心问题

为什么消融实验经常给出假阳性结果?

- **指标重叠**:两个指标实际测量同一件事,导致结果虚高
- **集合论评估陷阱**:集合论正确 ≠ 因果推理正确
- **随机基线错误**:随机猜测不应100%准确,否则评估函数有bug
- **表面高指标伪装**:高准确率可能只是"记忆"而非"理解"

## 关键原则(普适性)

### 1. 单一变量原则
每次实验只改变一个组件,否则无法归因。

**为什么重要?**
- 改变多个组件 → 无法区分哪个组件导致效果变化
- 单一变量 → 效果变化可明确归因到该组件

**实施方法:**
```
C1-baseline: 无任何组件
C2-仅A: 只加组件A
C3-仅B: 只加组件B
C4-A+B: 同时加A和B
```

---

### 2. 基线先行原则
先算随机基线,再评估模型表现。

**为什么重要?**
- 没有基线 → 无法判断模型是否真的有效
- 基线错误 → 整个评估框架失效

**实施方法:**
```python
# 先算随机基线
random_acc = (1/vocab_size) ** num_predictions

# 再算模型表现
model_acc = evaluate(model, test_data)

# 最后比较
is_effective = model_acc > random_acc * 10
```

---

### 3. 独立评估原则
评估指标之间不能测量同一件事。

**为什么重要?**
- 指标重叠 → 结果虚高,假阳性
- 独立指标 → 真实反映不同维度的能力

**检测方法:**
```python
if abs(metric_a - metric_b) < 0.001:
    print("⚠️ 指标重叠:两个指标可能测量同一件事")
```

---

### 4. 假阳性检测原则
任何高指标都必须通过假阳性检测。

**为什么重要?**
- 高指标可能是假阳性 → 错误的结论
- 假阳性检测 → 确保结果可信

**检测标准:**
```
指标 > 随机基线 × 10 → 通过
指标 ≤ 随机基线 × 10 → 假阳性,不可信
```

---

### 5. 可复现原则
记录所有配置,确保实验可复现。

**为什么重要?**
- 不可复现 → 结果无法验证
- 可复现 → 科学性保障

**记录内容:**
- 随机种子
- 超参数
- 数据集版本
- 代码版本
- 硬件环境

## 消融结构:两种模式

### 模式A:标准八组(C1-C8)

八组实验,覆盖从单组件到全组合:

| 编号 | 名称 | 说明 | 目的 |
|:-----|:-----|:-----|:-----|
| C1-baseline | 基准 | 无任何机制 | 建立基线 |
| C2-单组件 | 仅目标机制 | 只加待验证的机制 | 验证单组件效果 |
| C3-缺一 | 去掉目标机制 | 完整系统去掉待验证项 | 验证组件必要性 |
| C4-C6 | 逐步组合 | 每次多加一个辅助组件 | 验证组件交互 |
| C7-消融对照 | 已知有效的组件 | 验证消融框架本身是否正常 | 框架验证 |
| C8-all | 全机制 | 所有组件都加上 | 验证完整系统 |

**使用场景:**
- 验证新机制:用C2(单组件)看效果
- 验证组件必要性:用C3(缺一)看移除后影响
- 验证组件交互:用C4-C6看组合效果
- 框架验证:用C7确保消融框架本身正常

### 模式B:多组消融矩阵

当瓶颈候选跨多个维度时,用"分组消融矩阵"替代固定 C1-C8。每组内部结构不同,但共享同一基座。

**适用场景:**
- 需要同时排除多个维度(架构/信号/机制)
- 每个维度的实验设计不同(不能用统一的 C1-C8)
- 需要"一目了然"的结论矩阵

**设计原则:**
```
1. 列出所有瓶颈候选维度
2. 每个维度设计一组消融(组内结构可不同)
3. 所有组共享同一基座(预训练权重/数据/评估)
4. 汇总为"瓶颈候选 × 判定"矩阵
```

**参考案例**:V28 系列用 11 个消融点跨 3 组(基础机制/架构升级/信号形式),每组内部结构不同但共享 Stage1 预训练,最终产出 11 行判定矩阵。

---

### 共享预训练纪律

多组消融共享预训练权重时,确保对照组差异只来自 fine-tuning 阶段的单一变量。

**为什么重要?**
- 不共享预训练 → 对照组差异可能来自初始化随机性
- 共享预训练 → 差异只来自 fine-tuning 的机制差异

**实施方法:**
```
1. 训练一个共享的预训练基座
2. 冻结预训练权重
3. 每个消融组只训练差异部分
4. 所有组用相同的数据/种子/超参数
```

## 工作流总览

```
步骤一:设计实验
  - 确定要验证的组件
  - 设计C1-C8八组配置
  - 记录所有超参数

步骤二:计算随机基线
  - 确定评估指标
  - 计算随机猜测的准确率
  - 验证基线是否合理

步骤三:运行并归因
  - 运行所有实验
  - 计算每个实验的指标
  - 进行假阳性检测

步骤四:汇总表格
  - 生成对比表格
  - 计算增量贡献
  - 得出结论
```

## 关键判断口诀

- **"拆一个,看缺啥"** — 不是加功能,是移除功能看影响
- **"指标独立"** — 评估函数不能和训练目标用同一个计算
- **"基线先行"** — 先算随机基线,再算模型表现,最后比较
- **"单一变量"** — 一次实验只改一个东西,否则无法归因

---

## 四种假阳性模式(普适性)

| 模式 | 症状 | 检测方法 |
|:-----|:-----|:---------|
| **集合论陷阱** | 集合论指标高但因果推理失败 | 集合论正确 ≠ 因果推理正确 |
| **指标重叠** | 两个指标值几乎相同 | 检查两个指标是否测量同一件事 |
| **评估函数bug** | 随机基线≈1.0 | 验证随机基线是否合理 |
| **表面高指标伪装** | 指标高但规则泛化失败 | 测试模型能否适应不同规则 |

## 参考案例

本技能的方法论经过LMT-twister因果推理项目(V22-V26)验证。具体案例见各子技能的"参考案例"部分。

**核心验证结论:**
1. 单组件最优 ≠ 组合最优(消融实验的价值在于"拆"而不是"加")
2. 高指标不等于真能力(必须区分"记忆"和"理解")
3. 评估框架本身可能有bug(必须先验证评估函数的正确性)
4. 问题可能在表示能力,不在训练方式(消融实验能确认架构极限)
5. 训练数据多样性比架构复杂性更重要(多规则训练突破)
6. **E-V 闭环消融**:同回路 vs 分离回路的差异比任何组件开关都大
7. **触发策略比机制更重要**:cf_loss 触发从 READ-only 放宽到所有动作让信号从无到有
8. **维度排除法**:当多种变体在同一维度上收敛到相同结果,该维度不是瓶颈——先排除再优化
9. **共享预训练消融纪律**:对照组差异应只来自 fine-tuning 阶段的单一变量

## 案例研究

### LMT-twister 多规则训练突破

**背景**：V23-V26.6尝试了15种架构改进，都失败了。V26.7发现：问题不是架构，而是训练数据。

**发现**：
- 多规则训练（规则A/B/C混合）让rule_B从0%提升到10.22%
- 简单的多规则训练比复杂的架构更有效
- 模型需要见过多种规则，才能学会"规则"的概念

**教训**：
1. 先检查训练数据，在改进架构之前
2. 多样性比复杂性更重要
3. "记住"vs"理解"：多规则训练帮助模型从"记住"进化到"理解"

**详细案例**：[案例/LMT-twister多规则训练.md](案例/LMT-twister多规则训练.md)

### V27.2 E-V 闭环 6 组消融

**背景**：V27.1 加变分反事实 head 失败后，改为 E-V 闭环（同一回路、same-hidden-different-target），需要验证"同回路反事实训练"是否有效。

**设计**：6 组消融（C1-C6），正交扫描 cf_prob（0%/50%/100%）和 multi_rule（开/关），1 个种子：

| 编号 | cf_prob | multi_rule | 预期作用 |
|:----:|:-------:|:----------:|:--------|
| C1 | 0% | off | 纯基线，无任何反事实训练 |
| C2 | 50% | off | 反事实训练但单规则，验证 cf 自身效果 |
| C3 | 100% | off | 全反事实训练但单规则 |
| C4 | 0% | on | 多规则但无反事实，验证多样性单独作用 |
| C5 | 50% | on | **反事实 + 多规则，预期最强组合** |
| C6 | 100% | on | 全反事实 + 多规则 |

**发现**：
- C5（50% cf + 多规则）`pred=0.1063 > 基线 0.0783`，主任务不退步
- C5 `rC=0.1761` 规则 C 首现显著信号（规则 R 跟踪指标）
- C5 `off_cf=0.0567` 离线反事实泛化
- C2-C4/C6 全部退化 — 反事实训练需要适当比例 + 规则多样性同时存在

**教训**：
1. 触发策略比机制更重要：cf_loss 放宽到所有动作让样本从 ~50 增至 ~600
2. 多规则与反事实训练互补：单有任一都不行，两者结合才出信号
3. 架构局限：same-hidden-different-target 让模型无法区分事实/反事实查询
4. 33 版本中 V27.2 是唯一"主任务不退步 + 反事实有信号"的版本

**详细报告**：[V27.2 E-V 闭环报告](../../docs/v27_2_e_v_loop_report.md)

### 多组消融矩阵(维度排除法)

**背景**：需要同时验证多个瓶颈候选(架构/信号形式/机制),每个候选的实验设计不同。

**设计**：3 组消融,每组内部结构不同,但共享预训练基座:
- 组1(基础机制):2×2 析因设计(记忆×mode token)
- 组2(架构升级):4 种架构替换(同一指标)
- 组3(信号形式):独立配对+共享对照

**发现**：
- 组2 的 4 种架构全部失败 → 排除整个"架构"维度
- 组3 的双流隐藏是唯一有效机制 → 确认瓶颈在容量层
- 最终产出"瓶颈候选×判定"矩阵,一眼看出哪些路走不通

**教训**：
1. 消融矩阵≠固定 C1-C8,应根据瓶颈候选设计分组
2. 当多种变体收敛到同一结果,该维度被排除而非优化
3. 共享预训练确保对照公平——变量控制不止是"改什么",还有"锁定什么"
