# v0.2.3 — 抽取 + 消融可验证 (Extract & Ablation-Verifiable)

**作者**: plan-and-build phase
**日期**: 2026-06-30
**目标版本**: `@bolloon/bolloon-agent` 0.2.3 (从 0.2.2 升)
**commit 基线**: `52de1cf feat(agents): extract ToolRegistry + decideNext for消融可验证`

## TL;DR

本版本完成"消融思路"的核心动作:

1. **抽出 4 个独立可测模块** (parse-tool-call / session-store / tool-registry / react-loop), 全部不依赖 LLM
2. **新增 123 个测试 case**, 全套 621 / 621 全过, tsc 0 错误
3. **为 claude code / 外部 harness 提供 4 个独立可验证接口**, 用 import + 单测就能验, 不需要跑完整 bolloon CLI

未来版本 (v0.2.4+) 用本版本抽出的模块做"接续 / web / 决策迁移", 本版本不动 `runReActLoop` 主循环.

## 版本号语义 (按这次升级的 rationale)

`0.2.x` 是消融可验证性 (ablation-verifiability) 阶段. 改动都在内部抽象边界:
- 0.2.0–0.2.2: 累积业务功能 + fix (P2P / tool loops / wallet)
- **0.2.3 (本版)**: 把"业务功能"边界清晰化, 暴露成可独立 import 的纯模块
- 0.2.4+: 在已清晰的抽象上做"接续 + web + 决策迁移"

不是 0.3.0, 因为没有 breaking API change; 不是 0.2.4, 因为有较大边界变化 (4 个新模块).

## 完成的工作 (4 块)

### 块 A — parseToolCall 抽取 (commit `9f34691`)

**问题**: 原 `PiAgentSession.parseToolCall` 是 230 行的 private 方法藏在 4522 行的类里. 测试和真源码是两份独立实现 (= 测试通过 ≠ 真源码工作).

**抽取**: [src/agents/parse-tool-call.ts](../../src/agents/parse-tool-call.ts)
- `parseToolCall(content, ctx)` — 9 个正则 + alias resolve + 4-th fallback
- `isFinalResponse(content, ctx?)` — 剥离 think + tool_call 优先级 + final gen 标记
- `extractFinalAnswer(content)` — `<final gen>` 标记抽取

**顺手修的 bug** (消融过程发现):
- `<function_calls> + <parameter name="X">` 原 guard `/<\w+>[\s\S]*<\/\w+>/` 在带属性的 `<parameter name="command">` 起始标签上 false, 误走 key:value 分支

**测试**: [src/test/parse-tool-call.test.ts](../../src/test/parse-tool-call.test.ts) (28 个 case) + [src/test/parse-tool-call-loop.test.ts](../../src/test/parse-tool-call-loop.test.ts) (9 个 case, 端到端 mock 回路)

### 块 B — ToolRegistry 抽取 (commit `52de1cf`)

**问题**: `resolveToolName` 是 41 行硬编码 alias map, 跟 `parse-tool-call.ts` 的 `defaultResolveAlias` 是**两份独立 alias 表** — 改一边不生效另一边.

**抽取**: [src/agents/tool-registry.ts](../../src/agents/tool-registry.ts)
- `register / unregister / registerAll / list / get / has / clear / size`
- `resolve(name)` — alias 解析 + 大小写不敏感
- `invoke(name, args)` — 统一调度入口 (穿透 alias)
- `DEFAULT_ALIASES = Object.freeze(...)` — 默认 alias 表, immutable

**集成**: [src/agents/pi-sdk.ts:3612](../../src/agents/pi-sdk.ts#L3612) `resolveToolName` 从 41 行变成 1 行 `_toolRegistry.resolve(name)`. registerTools() 末尾镜像所有 tool 到 registry.

**测试**: [src/test/tool-registry.test.ts](../../src/test/tool-registry.test.ts) (23 个 case)

### 块 C — ReAct 决策层抽取 (commit `52de1cf`)

**问题**: `runReActLoop` 是 1100+ 行的 private 巨石函数, LLM 调用 + 状态机 + 终止条件 + 流式事件全揉在一起.

**抽取 (保守策略)**: [src/agents/react-loop.ts](../../src/agents/react-loop.ts)
- `decideNext(reply, ctx) → NextAction` — 纯函数, 输入 LLM 输出 + 已知 tools, 输出 4 种 kind:
  - `continue` (包括 sentinel / no-tool-no-final / signal-aborted)
  - `execute-tool` (name + args)
  - `final` (answer)
  - `parse-error` (raw name 不在 known)
- `isAiFailureSentinel(reply)` — 三种 bolloon 哨兵前缀
- `extractFinalText(reply, marker?)` — final 答案抽取
- `shouldForceExit / shouldHintToStopSameTool` — 终止条件

**没动的事**: `runReActLoop` 主循环 (风险太高 — 1100 行 + 15 个不变量 + 多次 incremental fix 历史的回归面太大)

**测试**: [src/test/react-loop.test.ts](../../src/test/react-loop.test.ts) (33 个 case, 全 pure-function)

### 块 D — 持久化 + 跨进程接续 (commit `e571107`)

**问题**: `messageHistory` 之前只能靠 `loadSessionKey` 在构造时读, **没有显式写入口**. claude code 想"完成 N 轮 → save → 新 session resume"完全无路.

**抽取**: [src/agents/session-store.ts](../../src/agents/session-store.ts)
- `saveMessages / loadMessages / listKeys / deleteKey`
- 原子写 (tmp + rename), JSON schema 校验, 防路径注入 (key 不含 `/` 不含 `..`)
- PathType 默认 `~/.bolloon/sessions/cache/`, 可注入

**集成 pi-sdk.ts**:
- `saveCurrentSession(key)` — 把当前 messageHistory 持久化
- `resumeSession(key, max=30)` — 从 disk 拉历史覆盖 messageHistory
- `peekSessionHistory(key, max=30)` — 只读, 不改状态
- `whenReady()` — 解决构造期间 `hydrateMessageHistory` 没 await 的 race condition (这个原 bug 在 commit `e571107` 顺手修)

**顺手修的 3 个原版 bug** (消融过程发现):
1. `_filterToMessage` 误过滤 `content:''` 的 tool-call-only assistant 消息
2. 旧 schema `{type: 'user'}` 没 role 字段却被原 hydrate 灌进 messageHistory
3. `hydrateMessageHistory()` fire-and-forget, loadSessionKey 在 race 下读不到

**测试**: [src/test/session-store.test.ts](../../src/test/session-store.test.ts) (19 个 case, 纯 IO) + [src/test/session-resume-e2e.test.ts](../../src/test/session-resume-e2e.test.ts) (11 个 case, 含 peerId 隔离避免 singleton 陷阱)

## 消融实验: 新引入的可验证接口

claude code / 外部 harness 可以独立 import 这 4 个模块, **无需启动 LLM / 启动 bolloon 服务**, 直接通过单测验证行为契约:

```ts
// === parse-tool-call ===
import { parseToolCall } from 'bolloon/agents/parse-tool-call';
const tc = parseToolCall(minimaxOutput, { tools: new Set(['shell_exec']) });

// === session-store ===
import { SessionStore } from 'bolloon/agents/session-store';
const store = new SessionStore({ cacheDir: '/tmp/test' });
await store.saveMessages('key', messages);
const restored = await store.loadMessages('key');

// === tool-registry ===
import { ToolRegistry, DEFAULT_ALIASES } from 'bolloon/agents/tool-registry';
const reg = new ToolRegistry();
reg.register(tool);
const canonical = reg.resolve('bash');  // 'shell_exec'

// === react-loop ===
import { decideNext } from 'bolloon/agents/react-loop';
const action = decideNext({ reply: llmOutput, knownToolNames: new Set([...]) });
```

每个模块都有完整测试覆盖, 任何破坏这 4 个接口契约的 commit 都会在 CI 立刻红.

## 没做的 (按优先级排序的未来工作)

### 🔥 优先级 1 (下一个版本, v0.2.4)

**真实 prompt 端到端验证脚本** — 解决"现在 621 个测试没有一个真走过 pi-sdk 的 ReAct path"的问题. 思路:
- 用 `pi-sdk.ts:L2558` 的 fallback 路径 (`createAgentSession` 无 LLM 时也能跑) + `peekSessionHistory`
- 写一个 `scripts/verify-pi-sdk-e2e.ts` 跑流程: `prompt → finalize → resumeSession → peek`

**修 pre-existing test 30s 超时** (`pi-sdk.test.ts > minimax LLM integration`). 该测试在 minimax API key 缺失下应 early return 但仍 30s timeout, 是阻塞 CI 的小石头. 解决: 测试启动 5 秒内如果 `isMinimaxAvailable()` 还没完成, 直接 skip 整个 it.

### 优先级 2 (v0.2.5)

**web 服务加 `?session=<key>` query param**. 改造 `[src/web/server.ts](../../src/web/server.ts)` 的 `createWebServer`, 让 URL 带 `?session=user-123` 时:
- 启动时 `createAgentSession({ sessionStore, loadSessionKey: 'user-123' })`
- 收到每条消息时 `await session.saveCurrentSession('user-123')` (持久化)
- 价值: web 用户每次访问自动接续, 跨刷新 / 跨天有效

这是 30 行增量, 覆盖了"真实用户能感知到的接续", 比给 CLI 加 `--save-key` 命令性价比更高.

### 优先级 3 (v0.2.6 或 v0.3.0)

**react-loop 接入 `runReActLoop` 主循环** (替换 1100 行决策逻辑). 风险高, **必须**子任务化:
1. 子任务 1: 抽 `decideMaxIterations / decideContextOverflow` 为独立函数
2. 子任务 2: 抽 AI sentinel 处理为 `handleAiFailure(reply, state)`, 替换 2558-2580 的 22 行
3. 子任务 3: 把"单次 step (buildContext + LLM call + decideNext + execute-or-final)" 抽到 `ReactiveStep.run()`, runReActLoop 只调它

每一步独立 PR + 测试 + 行为 diff 验证.

## 不做的 (被显式排除)

| 候选 | 为什么不做 |
|---|---|
| 把 SessionStore 串进 bolloon-cli 加 `--save-key` 子命令 | CLI 用户不是消融目标; LLM provider 全 disabled 真实用户跑不通; claude code 接入已通过 import 满足 |
| 1100 行 `runReActLoop` 一次性重构 | 风险收益比不划算; 见上"优先级 3"的子任务化拆分 |
| 加 `bolloon --chat-send / --sessions list / --sessions drop` CLI 子命令 | 同上 — 用户能感知的价值低于 web `?session=` 改造 |
| 迁移到 bolloon repo 之外的 bolloon-agent npm 包 | `package.json` 还没分离, 等本版本稳定再做 |
