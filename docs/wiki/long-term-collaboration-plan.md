## 0. 一句话

把"研究委托"做成**可核验、可结算、可追责**的流程:委托方出**任务书** → 受托方交**结构化交付物** → **机器初筛 + 委托方终审** → 链上**释放托管款**。钱不是对价的主体,钱是**"这件事真的发生过"的凭据**。

## 2. 合作模型(四步闭环)

```
① 委托方发任务书 (Task Spec)
      ↓ 写入 ~/.bolloon/tasks/ 并按 §6 通道对外可见
② 受托方接单 → 交付 (Deliverable)
      ↓ 结构化报告 + 逐条出处, 内容寻址 (hash), 通过 x402 交付
③ 机器初筛 (Machine Pre-check)  ← 自动, 可复现, 判据公开
      ↓ 通过 → 进入人工终审; 不通过 → 退回并点名失败判据
④ 委托方终审 → 链上 release 托管款
```

每一步都有**上链凭据**:`createEscrowV2`(立单) → `submitProofV2`(交凭证) → `releaseV2`(放款),或超时/争议走各自分支。

## 3. 任务书标准(Task Spec)

一期任务书必须包含以下字段(缺一不发):

| 字段 | 内容 | 为什么必须 |
|---|---|---|
| `task_id` | 唯一、稳定(派生链上 taskKey) | 幂等:同一 id 重发不产生第二笔付款 |
| `question` | 一句话可回答的问题(不是"研究一下 X") | 不可回答 = 不可验收 |
| `scope_in` / `scope_out` | 明确做什么、**明确不做什么** | 防止无限扩张 |
| `deliverable` | 见 §4 的形态与判据 | 验收标准前置 |
| `acceptance` | 机器判据清单(可复现命令或脚本) | 见 §5 初筛 |
| `budget` | `per_task / per_purchase / per_day` | 受 M1 上限约束 |
| `deadline` | 硬时限 + 超时后果 | 托管款有超时分支 |
| `provenance_required` | 逐条出处的**等级**要求 | HUSHFUSION 的既有纪律 |

## 4. 交付物标准(Deliverable)

**形态:结构化报告** = `report.json` + `report.md`

- `report.json`(机器读):每条结论一个对象,含 `claim` / `evidence[]` / `source_grade` / `confidence` / `gap?`
- `report.md`(人读):同一批结论的可读版,**结论数必须与 JSON 一致**(机器初筛会比对)

**出处三级(逐条标注,不许混用)**:

| 等级 | 定义 | 例(HUSHFUSION 场景) |
|---|---|---|
| `textbook` | 教科书/标准手册里的公式或常数 | `μ0H_P ≈ 1.84·T_c` 这类换算 |
| `measured` | 实测文献里的数据点(须给文献标识) | Nb₃Sn 的实测 T_c / H_c |
| `formalized` | **Lean 已证定理**(须给 `文件名:定理名`) | `PlasmaFusion.lean:confinement_iff_beta_le_one` |
| `derived` | 本次自算(须给**可复算的算式与输入**) | 代入具体场强算出的 T_c |

**硬规则**:凡 `derived` 必须**可复算**(给出算式 + 输入值 + 结果);凡引用必须**可定位**(到节/表/条目);**没有出处就不许写成结论** —— 只能写成 `gap`(缺口)。

---

## 5. 验收协议(Acceptance)

**两段式:机器初筛 → 人工终审**(你选定的模式)

**① 机器初筛(自动、可复现、判据公开)** 至少检查:
1. `report.json` 通过 schema 校验;`report.md` 结论数与 JSON 一致
2. 每条结论都有 `source_grade`,且 `derived` 条目**都带算式与输入**
3. `question` 的每一项**子问都有对应结论或显式 `gap`**(不许静默漏答)
4. 出处可定位(给出定位字符串非空且格式合法)
5. **反自相矛盾**:同一 claim 不出现两个互斥结论
6. 交付物 hash 与上链 `resultHash` 一致

初筛**只输出判据结果**(哪条过、哪条不过、为什么),**不改写受托方内容**。

**② 人工终审(委托方)**:
- 只在你点头后才 `release`;**不点头 → 不进 release**(可退回修订或走争议分支)
- 终审意见也留档(可作为下一期任务书的输入)

**三条禁令(不许破)**:
1. `payment uncertain ≠ payment failed` —— 不确定绝不重发
2. 争议期**不自动重付、不标 verified、不静默关闭**
3. 机器初筛通过 ≠ 已验收(它只是"够格送审")

## 6. 接单通道(缺口清单 —— 这是本次真正要补的工程)

现状只有三样薄基建:空目录 `~/.bolloon/tasks/inbox/`、x402 交付、IPNS 站点(`agent-sites.json` 只接受 IPNS)。**要让外部合作者/别的 Agent 能接单,至少要补**:

| # | 缺口 | 最小可用设计 | 状态 |
|---|---|---|---|
| C1 | **任务书对外可见** | 任务书以内容寻址文件发布(IPNS/静态),带签名;公开发布只含题目/判据/预算,**不含任何隐私** | 待做 |
| C2 | **接单登记(意向)** | 受托方提交"接单声明"(能力 + 报价 ≤ 上限 + 预计交付时间),登记在本地;**不上链**、不产生付款 | 待做 |
| C3 | **唯一性/防重复** | 一期任务**只接受一份交付**;重复 requestId 一律拒(已有幂等键机制可复用) | 部分已有 |
| C4 | **交付入口** | 交付物按内容寻址提交 + 校验 hash 与 `resultHash` 一致;失败**不静默**(报错给受托方) | 部分已有(x402) |
| C5 | **拒单与超时** | 到 deadline 未交付 → 走超时分支(**不自动重付**);拒单要留原因 | 待做 |
| C6 | **公示** | 公开页只显示"任务存在 / 已接单 / 已交付 / 已结算"四态(**不显示地址、DID、IP、正文**) | 部分已有(网关页四态) |

**隐私红线(对外一律)**:不出现钱包地址、DID、peerId、IP、任务正文;**地址与哈希一律短写**;合约地址不上页面。

## 8. 双方责任与红线

- **委托方(leo)**:出任务书、终审、按约定 release;不改写受托方内容
- **受托方**:交付可核验内容;不得伪造出处;不得把 `derived` 冒充 `measured`
- **系统(Bolloon)**:托管资金、留上链凭据、执行初筛;**永不**代替委托方终审、永不在不确定时重发、永不把单个节点看到的数据说成全网总量
- **钱的定位**:0.02 USDC 是**闭环凭据**,不是劳务对价;放大金额**必须**在 P0 跑通并积累若干期之后
