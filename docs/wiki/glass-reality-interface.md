# 眼镜端 Reality Interface —— 常驻感知 / 门控表达 / 可遗忘

> 承接 [three-terminal-product-vision.md](./three-terminal-product-vision.md) §5「Glass = Reality Interface」与 §10 存疑点 2/3。
> 本文只做一件事: **把「眼镜该多主动」这个问题从二选一拆成三轴, 并给出不可逆的那部分架构决策。**
> 一句话结论: **架构按「常驻」造, 默认按「静默」跑, 主动性是一个可升档的开关, 不是架构选择。**

---

## 0. 先把假二分拆掉

leo 的问题是二选一:

- A. 只是等待你说话的 Agent 入口 (被动)
- B. 持续理解现实上下文、在合适时机主动帮忙的常驻 Agent (主动)

**这个二选一是假的**, 因为它把三个互相独立的决定捆成了一根轴:

| 轴 | 内容 | 取值 |
| --- | --- | --- |
| **A 感知** | 什么时候在看/听 | 手动触发 / 唤醒词 / 场景触发 / 常驻缓冲 |
| **B 上下文** | 记住多长 | 当前这一句 / 最近 30–60 秒 / 今天 / 长期 |
| **C 主动性** | 谁先开口 | 用户先说 / 系统提示"可问" / 系统主动一句 |

把它们解开就看得出: **真正定义"生活在其中"的是 A+B, 不是 C。**

用户要的体验不是"AI 突然跟我说话"(那是打扰), 而是 **我开口的那一刻, 它已经在了** ——
我不用先说"刚才那个设备", 它知道"刚才那个设备"。

所以有这个名字: **在场 ≠ 开口 (presence ≠ speech)**。
"生活在其中"的度量单位是**谈前置**的 30 秒, 不是主动搭话的次数。

### 四象限 (按 A 感知 × C 主动性)

| | C=被动 (用户先说) | C=主动 (系统先说) |
| --- | --- | --- |
| **A=一次性感知** | ① 脸上的遥控器 (今天的实现) | ② 通知器 (推送式眼镜, 排除) |
| **A=常驻缓冲** | **③ 在场而安静 ← 目标** | ④ 搭话机 (打扰+隐私双爆, 排除) |

今天的代码落在 ①, 要去的目标是 ③。②和④都是**看着像进步的死路**: 它们把"信息变多"当成"帮助变多"。

## 1. 架构决策 (不可逆的部分)

### 1.1 交互链要从 3 段扩到 5 段

原文 `Hear → Understand → Act` 缺两段, 而缺的这两段恰好是产品差异所在:

```text
Sense (感知) → Understand (理解) → Decide (说/不说/等) → Act (行动) → Forget (遗忘)
                     ↑                                              │
                     └──────────── 记忆阶梯 (Memory Ladder) ─────────┘
```

- **Decide 是一等公民, 静默是一个合法且高频率的合法输出。**
  一个只会"响应"的系统不需要 Decide; 一个常驻系统没有 Decide 就必然变成打扰源。
- **Forget 不是隐私条款, 是产品功能。**
  "生活在其中"的反面不是"不常驻", 而是"变成录像机" —— 一旦所有东西都被存下来, 用户戴着的就是一台取证设备, 不是伙伴。

### 1.2 五个组件 (眼镜端运行时, 都要能单独关)

| 组件 | 职责 | 关键约束 |
| --- | --- | --- |
| **RealityRing (现实环)** | 滚动缓冲最近 30–60s 的低码率画面 + VAD 语音段 | **只在内存, 进程退出即消失, 永不落盘**; 1–2fps + 变化关键帧, 非连续视频 |
| **Situation (现场判断)** | 每 2–5s 判一次: 场景类别 / 是否换场景 / 是否有人说话 | 纯本地、纯轻量 (不是一次 LLM 调用), 只输出标签和变化量 |
| **IntentAnchor (意图锚)** | 当前"在做什么": 刚才说的话 / 按下的动作 / 长期 Intent | **不造第二套数据层**, 长期 Intent 复用 `~/.bolloon/world/` + `/api/intents` |
| **Gate (开口门)** | 唯一决定"是否打扰"的地方; 输出 speak / silent / ask | 静默是默认值; **每次静默必须留痕** (为什么没说), 可查可调 |
| **Ladder (记忆阶梯)** | L0 现实环 (秒级/内存/自毁) → L1 情景摘要 (场景级/落盘/默认 24h TTL) → L2 长期事实 | **L0 永不直接进 L2**; L1→L2 必须过一道提炼 + 用户可见 |

### 1.3 Gate 的判据 (需要 ≥3/5 通过才允许开口)

1. **相关性** — 与当前 IntentAnchor 有关, 否则不说 (好奇 ≠ 相关)
2. **时效性** — 现在不说就过期 (5 分钟后还成立的事, 不值得占用现在)
3. **不可自行获得** — 用户自己看不出来; 能看出来的就是噪音
4. **代价不对称** — 说错的代价 ≪ 不说的代价 (只有安全/错过窗口这类才配主动)
5. **预算** — 本小时主动次数 < N (默认 **2**), 且不在静音/勿扰状态

任一判定为"要更多上下文才能定" → `ask`, 可以安静地补一次感知再判, **但不能靠这个绕开预算**。

### 1.4 一句话原则 (One-breath rule)

主动提示 **≤ 1 句 ≤ 约 15 字**, 并且**必须挂一个可执行动作** (看一眼 / 要不要 / 忽略)。
做不到这句话就不许开口, 退回 silent。这条是防"眼镜变通知中心"的硬闸: 需要两句话的提示, 本质上是一次"打开 App", 那就等用户问。

### 1.5 主动性三档 (用户可见开关, 默认在中间)

| 档位 | 行为 | 谁默认 |
| --- | --- | --- |
| **静默档** | 只回答, 零主动 | 新用户 / 演示 / 会议中 |
| **提议档** | Gate 通过才说一句, **每场景 ≤1 次** | **默认** |
| **参与档** | 场景变化时可主动发起对话 | 只在显式开启 + 特定场景 (研究/会议/长任务) |

外加一个"物理可关"的软件等价: **长按 → 静音 30 分钟**, 显示一次倒计时, 可撤销。用户必须随时能把嘴闭上, 否则一次误报就永久卸载。

## 2. 任务调度: 眼镜负责"发起"和"交付", 不负责"跑"

眼镜不能也不该变成执行器 (电池/热/算力/中断)。分工:

```text
眼镜: 一句话 Intent + 现场快照 (≤3 帧 + 语音文本)   →  bolloon 节点: run id
bolloon: 意图路由 / Agent 发现 / 委派 / 长任务执行     →  眼镜: 单行进度 (同样过 Gate)
```

三条硬约束:

- 眼镜端必须能回答三个问题: **谁在跑 / 还要多久 / 上次推进是什么时候** (戴在脸上的人在看路, 看不了表格)
- 推送进度也要过 Gate: 只有 **"需要人决策"** 或 **"已完成"** 才允许推送; 中间态刷屏等于主动打扰
- 眼镜端无执行能力这件事要**明说**, 不许假装本地跑完了

## 3. 隐私 fail-closed 条款 (写死在架构里, 不留选项)

1. **默认不常驻开摄像头**。首次开启必须显式授权, 且有肉眼可见的采集指示 (首页角标)
2. **检测到他人正脸 / 屏幕 / 纸质文件 → L0 自动降级为不采集** (本地人脸/文本检测挡住, 不上传再判断)
3. **上传前一句话确认"这次带走什么"**: 用户开口那一段 + 最多 3 帧; 永不连续视频
4. **L0 不落盘**, 崩溃/断电即丢; 不能为了"以后有用"缓存
5. **L1 可查可删**, 默认 24h 过期; 过期不是清理任务, 是产品行为
6. **L2 只存提炼后的事实** (例: "leo 在做聚变线圈"), 不存原始音视频

> 宁可少一个功能, 不要一个"事后才解释"的采集行为。

## 4. 否决清单 (这四件事做了就要重写)

| 否决 | 理由 |
| --- | --- |
| 把手机 App 搬到眼镜 (菜单/列表/多页导航) | 进入/退出模型; 用户戴眼镜时手上有事、眼睛在看世界, 不在点菜单 |
| 眼镜上做聊天窗口 (滚屏消息历史) | 对话应是一条**字幕带**: 只留最后 2 条, 说完消失; 历史去 PC/手机看 |
| 信息流 / 卡片堆 | 原文已判死: 眼镜不是另一个 Feed |
| 用"主动推送次数"当北极星指标 | 会把团队推向 ②④ 象限; 正确的指标是 **静默率** 和 **前置在场率** |

## 5. 四个可测的指标 (替代"感觉更智能")

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| **前置在场率** | 用户发起的请求中, 回答用到了 L0 上下文 (无需重述) 的比例 | > 60% |
| **静默率** | silent 决策 / 全部 Gate 判定 | > 95% |
| **打扰成本** | 主动提示后 10s 内用户说"别说了"/摘下/关闭采集 的比例 | < 5% |
| **重述率** | 同一场景内用户需要重复解释同一件事的比例 | < 10% |

这四个数每个都挂在具体组件上 (Ring / Gate / Gate / Ladder), 不是抽象口号。

## 6. 与现状的差距 (诚实基线, 2026-10-28)

实测当前 `rokid/glass/` 的实现:

| 项 | 现状 | 差距 |
| --- | --- | --- |
| 结构 | `MainActivity.kt` 两个 Section (机会/联系人) + 方向键导航 + `Screen.CHAT` | 是"进入一个 App"的模型 ⇒ 落在 ①象限 |
| 感知 | `shootAndMatch()` 一次性拍照 → `POST /api/vision` | **无 RealityRing**, 拍完即忘 |
| 视觉 | `rust/.../vision.rs` = 离线 OCR + 关键词意图匹配 (`match_intent` / `default_intents`) | 是"读字", 不是"理解场景" |
| 语音 | `VoiceRecorder.kt` → `POST /api/asr` (本机 whisper) → `/api/chat` | 单轮, 无前后文 |
| 记忆 | 眼镜端零记忆 | 无 L1/L2 |
| Gate | 无 (只有人按键) | 整层缺失 |
| 遗忘 | 无 | 整层缺失 |
| 钱包 | `/api/wallet` 真实 RPC 余额 | 可用, 但不是眼镜的核心价值面 |

结论: **今天是一个可用的 ① 象限 P0 骨架 (能扫一眼、能说话), 不是错的东西, 但它不允许继续长 UI。**
风险在于: 继续在 MainActivity 里加 Section (任务/钱包/授权/消息) 是最省力的路径, 而这恰好是"脸上的手机"的复现。

## 7. 落地顺序 (每步都有可验判据)

| 阶段 | 做什么 | 验收 (真机/真跑) |
| --- | --- | --- |
| **P0 在场** | RealityRing (30s 内存缓冲) + 开口时自动附带最近上下文 (≤3 帧 + 语音) | 用户指着某物只说"这是什么", 回答中包含"环里的事实", **全程不出现"刚才那个"** |
| **P1 静默门** | Gate 落地, **只输出 silent + 留痕**, 不开口 | 走一个下午: 主动提示 **0** 次; `glass decisions` 能列出本可以说但没说的候选 + 每条原因 |
| **P2 提议档** | 只开最高信心类目 (安全 / 已约时间 / 眼前明确文字需读), 每场景 ≤1 | 真机一天: 误报 ≤1; 打扰成本 < 5% |
| **P3 委派** | 眼镜发 Intent → bolloon run → 单行进度 | 眼镜上说一句 → web 端真出现 run → 眼镜收到完成摘要; 中间态不刷屏 |

**顺序不可换**: P0 先给"在场", P1 先给"闭嘴", 然后才谈主动。反过来做 (先做主动) 一定会撞电池/隐私/打扰三堵墙, 而且用户关掉就再也不开。

## 8. 待 leo 拍板 (我不替他决定的三件)

1. **默认档位**: 提议档当默认 (我的建议) 还是新用户一律静默档 (更保守)。
2. **L0 是否允许"用户显式开启的常驻"**: 我倾向 P0 只做"按键前后 30s 缓冲"(零常驻), 常驻留给 P2 后按用户自选。这决定电池预算和合规口径。
3. **眼镜上要不要保留 `Screen.CHAT`**: 我建议改成"字幕带 + 最后 2 条", 去掉可滚动的聊天页。

---

## 9. 一句话复述 (给未来的 session)

> 眼镜不是"更主动的助手", 也不是"更小的手机"。
> 它是一台**默认安静、但你开口时已经知道刚才发生了什么**的设备;
> 它的技术核心不是模型, 是 **现实环 + 开口门 + 遗忘阶梯** 这三个组件;
> 而"主动性"只是这三件东西之上的一个开关。
