# Bolloon 0.6.1 — Kernel 驱动的 Agent

> 版本号 = `package.json` 的 `version` = git tag 名 = Release 名 = `v0.6.1`。

## 亮点

> 这一版最值钱的变化：**Agent 的执行核心从「Pi 驱动」换成了「Kernel 驱动」**。

- **六件事全部由内核承担**：回合循环、工具门、运行事实、通道状态、通信入口、模型选择。
  推理层（Pi）降为可替换的适配器：换掉它不影响上层协议。
- **第二个推理适配器可用**：`BOLLOON_NATIVE_ADAPTER=1` 启用一个不 import 推理层、`fetch` 直连的实现
  （自建超时 / 退避 / 取消 / 4xx 不重试），并与原适配器**过同一套门**（工具调用恰一次 / 拒绝零执行）。
- **模型调用经内核运行时**：回合向进程内模型运行时**只读取租约**，超时 / 取消 / 退避 / 熔断 / 回退 /
  记账 / 连接池 / 能力检查由运行时统一负责；传输仍是原客户端 ⇒ 对外行为不变。

## 新增能力

- 内核端口：`run-lifecycle`（开始运行 / 记步 / 结束 / 存档）与 `transport`（send / broadcast / peers）。
  统一写法：端口注入 · 未注入即拒 · 一律返回结果对象 · `{ok:false}` 归一化 · 审计流水。
- 只读投影入口：把「当前有效模型选择」投成快照，**缺 provider/model 就返回 null**，不编一个假的顶上。
- 写类工具成功返回自带**落盘核对**：`[已核对] 文件已落盘: <path> (N 字节, mtime)`。
- 中止语义归内核：`POST /api/chat/abort` 按通道扫内核 actor，返回**真的中止了几个**；
  没在跑时如实回 `aborted: false`。
- 同步读也走端口：对端列表在有同步调用点的地方保持同步签名（未注入时**明说读不到**，不假装"没有对端"）。

## 修复

- **回合在第 2 轮中断**：适配器创建时取一个长期租约、用完归还 ⇒ 第二次调用撞上运行时守卫「租约已归还」。
  改为**每次调用现取租约**（连接由池复用），并把反面形状钉进门里。
- **非 429 的 4xx 被当网络错重试**：一个 400 被重复发出 4 次 ⇒ 标记不重试并原样抛出。
- **换适配器仍被原适配器的可用性卡死**：三道回合入口的可用性判据改为问**当前适配器**。
- **运行状态迁移改经控制面**：被拒时不再写降级记录（口径保真）。
- **收尾自检在生产从未跑到**：通路提前 return ⇒ 现在三条路径都挂上。
- **消融实验报告谎报环境**：报告头原为写死值（Windows + 另一家 provider）⇒ 改为真读本机与配置，
  读不出就如实写"读不出"。
