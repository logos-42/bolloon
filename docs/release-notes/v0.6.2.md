# v0.6.2 —— 群聊能用了: AI 自己入群 · 自己读 · 自己 @ 人 · 自己发言

一到两句话: 这一版把 OrbitDB 群聊从"打不开"修成"**AI 自己就能用**" —— 修好初始化与错误话术,
把群工具从 4 个补到 8 个（@成员 · 回复某条 · 图片/音频 · 分支话题），再加一条**自主回路**：
AI 自己能读群、自己判断该不该开口、自己发言。

## 修好了什么

- **群聊打不开的真身**：`Database failed to open` 背后是 `IO error: lock …/orbitdb/stores/keystore/LOCK:
  Resource temporarily unavailable` —— 同机同一份库只允许一个进程写。
  现在打不开会明说「**库被另一个实例占着**」并给两条出路（退出其它实例 / 设 `BOLLOON_HOME`）。
- **隔离真的隔离了**：`BOLLOON_HOME` 以前对这个模块**不生效**（"隔离运行"其实在开真实 `~/.bolloon/orbitdb`）。
  现在 dataDir 走 `${BOLLOON_HOME:-~/.bolloon}`。
- **不再无声挂死**：打开库的三步（起 helia / 建 OrbitDB / 开 CID 库）全部有界等待（默认 20s，
  `BOLLOON_ORBITDB_STAGE_TIMEOUT_MS` 可调）；以前卡住就是永远卡住。

## 群工具: 4 → 8 个（AI 自己就能用）

| 工具 | 干什么 |
| --- | --- |
| `group_join` | 拿邀请链接自助入群（幂等） |
| `group_list` | 列出本机已加入的群 |
| `group_read` | 读群消息 —— 输出里带 `#消息id` · `@谁` · `↩#被回复的id` · `⎇分支` · `[图片/音频 cid]`；可按分支过滤 |
| `group_say` | 发言（可带 `mentions` 数组或逗号串 —— 字符串也收） |
| `group_reply` | **回复某一条**（用 `group_read` 里的 `#id`） |
| `group_attach` | 发**图片/音频/文件**：字节进内容寻址层，消息里只放 CID（本机文件自动算 CID 并入库） |
| `group_branch` | 开**分支话题**（一个群同时聊多件事不互相打断） |
| `group_members` | 看群里谁发过言 |

- 发言一律走**唯一出口** `sendTrailMessage`：带上**隐私红线闸**（地址 / DID / peerId / multiaddr / IP / 私钥形态
  一律不许出网），**@ 的内容也过闸**（有人把 DID 写在 @ 里也拦得住）。
- 消息记录是**向后兼容**的：不带新字段时记录里**一个键都不多**（老读者读到的一字不变）。

## 自主回路: AI 自己读群 · 自己判断 · 自己发言

`group_autopilot` 工具（action: `run` / `start` / `stop` / `status`）:

- 只在 **① 有人 @我** 或 **② 有人在提问 / 请人做事** 时开口；其余**静默**（宁可不做，不许刷屏）。
- 冷却 60s，每小时每群最多 6 次；处理过的消息记进 `seen`，**同一条只说一次**。
- 被 @ 或看到提问时，会**回复那一条**并 **@ 提问的人**。

真机实录（隔离环境）:

```
#zdpuAodp8f | 这个口径谁来确认一下？                    ← 别人发的提问
#zdpuB2wVhe replyTo=zdpuAodp8f @审稿人-张三 | 收到 —— 关于「这个口径谁来确认一下？」，我这边跟进。
```

## 如实说明（这一版**没有**解决的）

- **跨机读群：已实测成立（2026-10-02 补测，真两节点子进程）** —— 我先前写"未实测"是**保守过头**（早先还有一版写成"缺 bitswap"，那是错的）。用仓里既有的真两节点门（`scripts/verify-group-replication.ts`，跑法带
  `BOLLOON_ORBITDB_LEAN_ROUTING=1 BOLLOON_ORBITDB_NO_MDNS=1`）验过：
  · 存储层（S1–S4）**8/8 稳定**：新节点拿 101 条（1.0s）· 迟到者拿 1001 条长历史（20s）· 供块方下线后新节点确实拿不到（反事实）· 断网分叉重连后两侧 21 条收敛，集合指纹逐字相同。
  · **群模块路径（S5，即 `group_join` / `group_read` / `group_say` 背后的同一批函数）**：A 建群写 51 条 → B **拨号入群并读到 51 条**（858ms）→ B **回写成功**（非创建者可写）→ A 重启按 groupId **读回 52 条**。
  **成立的前提（缺一条就不成立，如实写明）**：`BOLLOON_ORBITDB_LEAN_ROUTING=1`（否则路由服务会拖住块交换）· 两个节点**同时在线** · **供块的一方必须活着**（写完就退的进程，别人拉不到它的块）· 读的一方要能连上（`NO_MDNS=1` 时只能靠显式拨号）。
  ⚠️ 另有一条产品语义容易踩：**建群默认是「创建者独占写入」**（2026-10-01 P1 起）⇒ 要让入群的人能发言，建群时得显式 `acl:'open'`（谁拿到邀请链接都能发言）；独占群下别人写不进去是**正确行为**，不是 bug。
- **群列表文件仍不认 `BOLLOON_HOME`**：`gateway-groups.json` 在真实 HOME 下 ⇒ 多个隔离环境会把群名单混在一起
  （所以隔离环境里 `group_list` 可能列出别的环境建的群，读它会报"不可达"——那是预期，不是坏了）。
