# Bolloon 真正要做的事

> **写于 2026-06-10,经过 6 维对比、3 个 skill 联合诊断后重新校准**
>
> 本文是 Bolloon 的"第一性原理"文档。所有其他文档(README、想法.md、findings.md、task_plan.md)都应与本文保持一致。如果不一致,**以本文为准**。

---

## 一、一句话定义

> **Bolloon 是 A 和 B 对接判断力的协议层。**
>
> 在 A 和 B 一起做重要决定之前,让 A 的 3 个反方观点被 B 看见,B 的 3 个反方观点被 A 看见。

---

## 二、不是做什么(明确排除)

为了防止叙事漂移,把"不做的事"先钉死:

| ❌ 不做 | 为什么不做 |
|---------|------------|
| 不做"个人判断力外挂"(单人 Agent) | 红海。ChatGPT / Claude / Cursor 都在做。 |
| 不做"通用聊天 / 群聊" | 模型 A 视角下的工具叙事,不是协议型愿景。 |
| 不做"AI 协作画布 / 多 Agent 编排"(Devin / LangGraph 那一类) | 重运营、重交付周期,和协议愿景不匹配。 |
| 不做"AI 投资/理财/复利"(那个是另一个 skill 的话题) | 跟判断力对齐没关系,不要混。 |
| **不为了付费而付费** | 模型 B 还没验证前,付费模式会污染信号。 |

## 三、协议愿景(模型 B)

### 3.1 协议语义(已确定)

```
bolloon init            // 初始化本节点的"判断力协议身份"
bolloon connect @B      // 邀请 B 接入协议(双方各建立握手)
bolloon ask @B "X"      // 就决策 X 发起协议:输出 3 个反方给对方看
bolloon align @B "X"    // 双方基于"反方互见"做对齐协商
bolloon reflect         // 回顾本节点近 N 次协议调用,沉淀判断模式
```

### 3.2 协议消息类型(待工程化)

| 消息 | 方向 | 含义 |
|------|------|------|
| `manifest_request / payload` | A↔B | 节点握手后互换"我有哪些判断能力" |
| `ask` | A→B | A 就决策 X 发起 3 个反方蒸馏 |
| `dissent` | A↔B | 双方的反方观点互见 |
| `align` | A↔B | 基于反方互见形成对齐结论 |
| `reflect` | 本地 | 把本次协议调用归档进"判断力轨迹" |

> **当前代码进度**:`manifest_request / payload` 已实现(`src/agents/agent-manifest-protocol.ts`)。  
> `ask / dissent / align / reflect` 是**待实现的协议消息**,优先级最高。

### 3.3 协议四要素对照(为什么是"协议"不是"工具")

| 协议要素 | HTTPS 类比 | Bolloon 协议 |
|----------|------------|--------------|
| **握手** | TLS Handshake | `bolloon connect @B` |
| **语义** | GET/POST/PUT/DELETE | `ask / dissent / align / reflect` |
| **调用** | HTTP Request/Response | A ↔ bolloon 节点 ↔ B |
| **客户端** | Chrome / curl / Postman | CLI / Web / Electron / 其他 Agent |

## 四、为什么是真需求(6 维验证 + 现实校准)

### 4.1 6 维对比(理论层)

| 维度 | 模型 A(单人辅助) | **模型 B(协议层 · 我们的选择)** |
|------|------------------|----------------------------------|
| 位置 | 红海(个人辅助) | **蓝海(协作协议层)** |
| 搜索意图 | "决策辅助"(弱意图) | **"协作协议"(强意图)** |
| 装监控感 | 中(个人痛苦) | **极强(关系痛苦)** |
| 杠杆 | F=0 时无意义 | **N² 网络效应,一旦起网 = 杠杆点** |
| ROI 三特征 | 0.5/3 | **3/3(成本倒挂/风险不可逆/流程强依赖)** |
| 复利 | 1×1 线性 | **N×N 超线性** |

### 4.2 现实校准(诚实层)

> **6 维对比的"理论 8-9 分"≠"现实已成立"。**

| 现实 | 真实状态 |
|------|----------|
| 用户数 | **0** |
| 真实场景验证数 | **0** |
| 协议消息已实现的 | 仅 `manifest_*` |
| 协议消息待实现的 | `ask / dissent / align / reflect` |

**结论**:理论上是真需求,**工程底子是协议层(已搭),但"协议语义"(ask/dissent/align)还没接上**。  
所以下一步**不是"重构工程",而是"先把 ask/dissent/align 这 3 个协议消息发出去给真人用"**。

## 五、阶段 0(接下来 30 天 · 不改架构 · 不改付费)

> 这是**唯一**在做的重要事。其他都是噪声。

### 5.1 阶段 0 目标

**找到 5 对(10 个)真实的人,让他们用 bolloon 就 1 个真实场景做 1 次"反方互见"。**

| 不做 | 做 |
|------|----|
| 不做付费模式 | 做 1 条贴发出去,看回声密度 |
| 不做产品改名/重定位 | 做找 5 对潜在合作者名单 |
| 不删任何子系统 | 做让那 5 对人真实用 1 次 |
| 不为"用户量"焦虑 | 做录 1 条视频:"5 对人用 bolloon 的过程" |

### 5.2 30 天节奏

| 周 | 动作 | 产出 |
|----|------|------|
| W1(Day 1-7) | 写第 1 条贴(中文即刻版) | 1 份贴草稿 + 24h 反馈 |
| W1(Day 3-7) | 找 1 个朋友/合作者用 bolloon 真实对接 1 次 | 1 张"双方反方互见"截图 |
| W2(Day 8-14) | 把 W1 体验发第 2 条贴 | 第 2 条贴 + 1 个公开 use case |
| W3-W4(Day 15-30) | 找 4 对真实合作者(8 人)用 bolloon 做 1 次真实场景对接 | 4 张"协议型 use case"卡片 |
| W4 末 | 录 1 条 2 分钟视频:"5 对人用 bolloon 真实对接的过程" | 1 个公开验证(可发 X/即刻/B 站) |

### 5.3 24 小时反馈指标(贴发出去后看)

| 指标 | 目标(72 小时内) | 含义 |
|------|------------------|------|
| ❤️ 点赞 | 50+ | "有用"信号 |
| ⭐ 收藏 | 20+ | "想留存"信号 |
| 💬 评论(具体场景) | 10+ 条"我也是" | **真痛点** |
| 🔁 转发 | 5+ | 暴露自己也有这个问题 |
| 📨 私信问"怎么用" | 3+ | **真潜在用户** |

### 5.4 3 种结果 → 3 种动作

| 反馈密度 | 动作 |
|----------|------|
| **3 指标达成** | 启动"找 5 对人"真实用 bolloon(进入 W2-W4) |
| **1-2 指标达成** | 重写"那个问题"——你问的可能不够准(用 product-thinking 重构) |
| **0 指标** | **不改贴,先看 1 周**——很可能发错圈/发错时间。叙事本身不改 |

## 六、第 1 条贴(可直接发)

```
我每年最贵的几次失败,不是判断错——是我和对方"判断没对齐"。

最经典一次:跟一个潜在合伙人谈了 2 小时,谈完都不知道他到底怎么想。
我有 3 个顾虑没说,他有 3 个顾虑没问。
后来合作黄了,他说"我以为你不感兴趣"。

后来我数了下,这种"谈崩"在我身上发生了 3 次:
1. 跟潜在合伙人(信息差 → 合作黄)
2. 跟老婆关于"要不要换房"(判断盲点 → 反复吵)
3. 跟一个想挖我的老板(双方反方看不见 → 错过机会)

这 3 次的共性:
- 不是判断错,是 A 和 B 的判断"没对齐"
- 不是不努力沟通,是沟通时"反方观点"看不到
- 不是没工具,是有工具但工具是给"个人"用的,不是给"关系"用的

所以我在做一个东西 bolloon,核心就 1 件事:
让 A 和 B 在做决定前,把双方的 3 个反方观点"互相可见"。

但不卖产品,先问你一个问题:
你最近一次"谈崩"是什么场景?
你和对方的哪 3 个反方,本来应该互相看见但没看见?

(我想看 100 个人里有多少能"对上号"——如果 10% 以上能说出具体场景,就是真需求。)
```

| 不动 16 个 Skill Adapter | Skill 是工具,不是协议。阶段 0 不用 Skill。 |
| 不发 v0.1.33 / v0.1.34 | 阶段 0 不需要新版本号。 |
| 不写 Phase 2-6 的 task_plan | 阶段 0 验证完再决定要不要继续。 |

## 九、给未来的自己(避免叙事漂移)

> 写这段是为了**半年后回头看,不被当时的我骗**。

1. **"协议愿景"不等于"协议已成立"**。60K+ 行代码 + 333 个 commit 搭建的是协议底层,不是协议本身。**协议 = ask/dissent/align 在 5 对真人之间跑通的那一天**才算成立。
2. **"6 维对比 8-9 分"≠"已验证"**。所有分数的分母是 0,真需求必须用真人、真场景、真反馈验证。
3. **"阶段 0"是项目从"工程深井"爬到"用户地面"的绳索**。30 天不爬,后面所有代码都是在深井里打转。
4. **付费模式是阶段 2 的事,不是阶段 0 的事**。阶段 0 把"反方互见是真需求"验证完,才谈付费。
5. **不要为了"看起来在做事"而做事**。加 LLM Provider 是看起来在做事,删 LLM Provider 也是看起来在做事,什么都不做也是看起来在做事。**唯一看真需求信号的事:5 对真人 × 1 次真实场景 = 5 张 use case 卡片**。
